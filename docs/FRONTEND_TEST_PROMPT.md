# 前端业务场景测试约束提示词

将下列提示词与具体需求、Bug 日志或改动文件一起使用。先遵守根目录及 `frontend/AGENTS.md`；本提示词不授权运行测试、安装依赖、构建、浏览器验收或 Git 操作。

```text
请为 Rename Studio 的这次前端改动维护业务场景测试。

先阅读相关组件、直接调用方、Hook、Store、API 契约和已有测试。
列出“业务风险 → 最小验证层级 → 操作入口 → 直接结果 → 关联状态”。
优先扩展已有场景；需求不明确时直接提问，达成共识后再实施依赖该答案的修改。

编写约束：
1. 按“准备场景 → 执行真实操作 → 检查业务结果”组织，名称说明触发条件和预期行为。
   不为覆盖率、框架保证、不可达状态、纯样式或简单文案增加测试。
2. 准备数据复用 src/test/fixtures.ts，可显式覆盖身份、名称、权限、位置和账号。
   工厂只生成输入，不实现重命名、排序、选择过滤或被测预期算法。
3. 被测试的选择、规则编辑、排序、导航、预览、执行或重置，必须通过其真实入口触发。
   setState、Query 缓存注入只用于前置条件、外部响应或服务端状态变化，不能替代被测操作。
4. 保留真实 Hook、Zustand、QueryClient 和业务纯函数，只模拟 API、浏览器等外部边界。
   vi.mock 写在测试入口；显式安装 workspace 生命周期，不依赖辅助模块导入副作用。
   组件用角色、可访问名称和用户可见结果定位；避免 MUI 类名、DOM 层级和大快照。
5. 根据实际影响检查关联状态：
   - 选择/规则/排序变化：选择集合、旧预览失效、替换 ID、未执行、原始任务快照。
   - 连接/版本/账号/目录变化：不透明位置、查询隔离、旧任务清理、迟到响应和原连接释放。
   - 执行结果：确认的 current_file 身份、列表缓存、任务记录、剩余选择与原始快照一致。
   - 部分失败/未知/缺失结果：只重试明确失败项，不重选成功项，不自动重放未知项。
   - 语言/偏好/重置：真实文件和账号数据保留，任务与请求不被无关操作改变；失败可恢复。
   只断言本场景相关的关系，不机械复制全部状态。
6. 异步响应复用 deferred<T>()，用 waitFor 等待具体请求或状态，在 act 中结束响应。
   禁止固定 sleep、反复轮询内部实现、扩大超时、清空错误或跳过有效断言来使测试通过。
7. 纯业务变化表用 it.each；不同操作和不同生命周期不要硬塞进一个复杂循环。
   先在 Store / Hook 覆盖组合，工作台只保留代表性跨模块接线，不重复全部矩阵。
8. 合并或移动测试前记录有效断言的承接位置，不删除仍保护业务契约的测试。
   新增场景或移动入口后同步 docs/FRONTEND_TEST_CASES.md，不手工维护用例总数。
9. 修改 CI 时保留必需检查 Frontend tests and build；测试 PR 完整差异分流，删除、
   重命名、默认词典结构变化和混合 PR 不得误判为纯翻译；不能顶层 paths 跳过必需检查。
   普通 push 不触发 Frontend CI，Release 仍只 build，不增加 E2E 框架或覆盖率门槛。
10. 完成后说明修改文件、删减/合并逻辑与原因、覆盖与剩余风险、建议人工运行的命令。
    可做差异、AST、语法等静态检查；不得称为类型检查、测试通过、构建或浏览器验证。
    npm ci / npm test / npm run check / npm run build、真实云盘和 Git 操作遵守项目授权流程。
```
