# Windows / macOS 启动与人工验收

## Windows 用户启动

要求 Windows、交互式 PowerShell 5.1+、已安装的 Python 3.12+。用户不需要 Node.js；首次安装运行依赖需要联网。项目目录必须可写。

在项目根目录执行：

```powershell
.\Start.ps1
```

也可在资源管理器中右键 `Start.ps1`，选择“使用 PowerShell 运行”。如果系统执行策略阻止脚本，可在信任发布包后使用只对本次进程生效的命令；脚本自身不修改执行策略，不请求管理员权限：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1
```

可选参数：

```powershell
.\Start.ps1 -PythonPath 'C:\Path To Python\python.exe'
.\Start.ps1 -NoBrowser
```

脚本从自身目录定位项目，不依赖终端当前目录。默认固定访问 `http://localhost:8000`，服务只监听 `127.0.0.1:8000`。发布模式仅覆盖子进程的前端 Origin 和 OAuth 回调，仍使用 `http://localhost:8000/auth/storage/callback`；其他后端配置保持现有行为。

保持启动窗口打开。按 **Q 或 Ctrl+C** 安全退出：停止接受新请求，等待当前请求结束，再清理 Provider 客户端。关闭浏览器不会停止服务。服务进程持有 PowerShell 进程句柄，在该进程结束时也会尝试正常退出；不要将强制终止后端、断电或反复强制关闭窗口视为安全退出。若关闭的是脚本而宿主 PowerShell 进程仍在，不能依赖进程监测代替 Q 退出。

## macOS 用户启动

要求 macOS、交互式终端和预先安装的 Python 3.12+。在终端执行以下命令，不要求给脚本添加执行权限；路径含空格或中文时保留引号：

```bash
bash "/项目完整路径/Start.sh"
bash "/项目完整路径/Start.sh" --python "/Python完整路径/python3"
bash "/项目完整路径/Start.sh" --no-browser
```

脚本兼容系统自带 Bash 3.2，从 PATH、常见 Homebrew 位置和 python.org Framework 位置探测 Python；不自动安装 Python、Homebrew 或开发工具。自动探测跳过 `/usr/bin/python3` 系统入口，避免触发开发工具安装；非标准安装位置可用 `--python` 指定。Python 检测阶段的错误显示在终端；选定 Python 后的启动和安装日志写入 `.runtime/logs`。

`Start.sh` 默认由 macOS 用户使用，只负责 Python、交互式终端检查和参数传递，不校验操作系统；随后以 Python 标准库控制器 `backend/scripts/start_macos.py` 管理虚拟环境、文件锁、日志及子进程。不依赖外部 `flock` 命令。端口检查使用 macOS 自带的 `lsof`，仅查看、不关闭占用进程。默认地址、发布模式和 OAuth 回调与 Windows 一致。

保持终端打开，输入 **Q 后按 Enter**，或按 **Ctrl+C** 退出；创建环境和安装期间也可取消。退出时通过停止文件通知服务，等待当前请求完成，不超时强杀服务。控制器处理 SIGTERM/SIGHUP；若控制器直接消失，服务也会通过父子进程关系变化尝试正常停止。强杀后端或断电仍可能留下未知写入结果，必须核对真实文件，不要盲目重试。

依赖和成功指纹仍保存在 `.runtime`，虚拟环境 Python 位于 `.runtime/venv/bin/python`。不要跨系统或跨 CPU 架构复制虚拟环境；在目标机器重新创建。项目移动、Python 变化或创建环境中断后，退出并移走 `.runtime/venv` 再启动。不要删除 `backend/settings.json`；跨系统迁移的旧 Local 连接路径需按实际情况重新配置。

macOS 的启动与固定依赖安装尚未实机验证，不能将语法检查视为平台支持验收。若 Python 发行版没有 Tk，现有系统目录选择器不可用，可使用已有的绝对路径输入功能；这不是启动脚本自动安装的系统组件。

## 环境、日志与更新

- `.runtime/venv` 是发布运行环境，独立于开发用 `backend/.venv`。脚本直接调用其中的 Python，不激活环境，不安装开发依赖。
- `backend/requirements-runtime.txt` 固定运行依赖及传递依赖版本。脚本比较其 SHA-256，并离线检查安装版本及核心包导入；通过时跳过 pip。变更或损坏时重新安装，只有安装与检查都成功才记录指纹。失败后可修复网络或 pip 配置再启动重试。
- 该依赖清单取自当前开发环境的包元数据，尚未完成全新环境安装验收。发布前由开发者在 Python 3.12 和实际支持的较新版本验证，并与 `pyproject.toml` 的运行依赖保持一致；不要直接导出包含 pytest 等开发工具的完整 freeze。
- `.runtime/logs` 保存启动、虚拟环境创建、安装、依赖检查与服务的输出和错误。启动时保留最近 40 个历史日志文件；本次日志另外保存。启动错误会显示具体阶段并等待 Enter，不自动关闭错误窗口。
- 项目移动、Python 路径或版本变化、虚拟环境创建中断时，脚本明确要求重建：关闭项目，将 `.runtime/venv` 移走或删除，再启动。无需删除 `backend/settings.json`。
- 同一项目启动锁覆盖安装与运行；再次启动不会新建服务，就绪时只打开已有页面。不同目录的项目副本共用默认端口，第二份会报告端口冲突。脚本不会自动换端口或关闭占用程序。
- 更新时先退出，再替换程序文件及整个 `frontend/dist`；保留 `backend/settings.json`、用户 `.env` 与 `.runtime`。前端资源必须整体更新，不能只替换 `index.html`。不要在服务运行期间覆盖文件。

## 开发者发布与开发边界

开发者执行现有前端构建命令，把完整 `frontend/dist` 放入发布包。脚本不执行 npm、构建或下载前端。

Windows 发布包至少包含 `Start.ps1`、`backend/app`、`backend/pyproject.toml`、`backend/requirements-runtime.txt` 和完整 `frontend/dist`；macOS 包使用 `Start.sh`，并额外包含 `backend/scripts/start_macos.py`。通用包可同时包含两个入口。Shell 文件必须保留 LF 换行（仓库 `.gitattributes` 已约束）。不要打包开发虚拟环境、`.runtime`、`node_modules`、用户 `.env` 或包含凭据的 `backend/settings.json`。

发布入口 `app.launcher` 使用单个 Uvicorn worker，不启用 reload。发布应用保留现有根路径 API 和 OAuth 回调，并增加 `/api` 挂载，静态页面在 `/`；`/api` 下不存在的路径不会返回前端 HTML。启动时检查 `index.html` 直接引用的本地资源；动态加载的页面资源仍需通过完整 dist 发布及 UI 验收确认。前端当前没有 URL 路由，静态服务不增加 SPA 任意路径回退。

开发仍使用 `app.main:app --reload` 与 Vite；无需前端构建产物。原有测试入口和业务逻辑保持不变。`app.main` 的应用偏好校验错误脱敏改为根据匹配路由判断，确保挂载在 `/api` 下时也不返回输入内容。

## 人工验收清单

请在测试文件夹与测试 OneDrive 项目上操作。本次交付只做静态检查，以下项目需要人工执行。

| 场景 | 操作与预期 |
| --- | --- |
| 全新安装 | 使用无 `.runtime` 的发布包和 Python 3.12；只安装运行依赖，页面就绪后自动打开，不要求 Node.js，不产生 reload 或多 worker 进程。另在实际支持的较新 Python 版本重复。 |
| Python 探测 | 分别验证只有 `py`、只有 PATH 中的 Python、多个版本、只有旧版本、无 Python、只有 WindowsApps 别名；可用版本能启动，其余给出安装/指定路径提示，不自动安装系统 Python。 |
| 指定解释器 | 用含空格路径的 `-PythonPath`；有效 Python 可用，旧版本和无效路径报错。 |
| PowerShell 与路径 | Windows PowerShell 5.1 与 PowerShell 7；中文/空格目录、从其他当前目录启动、资源管理器右键启动均正确。执行策略受限时确认提示/手动启动方式。 |
| 后续离线启动 | 首次成功后断网再启动；显示跳过 pip，页面与本地功能可用。云盘功能仍需要联网。 |
| 依赖升级与修复 | 在发布包副本中更新固定清单到已确认兼容版本，确认重新安装；删除一个核心依赖后启动，确认检查失败并修复，成功后再次启动跳过安装。 |
| 安装失败与重试 | 使用无环境副本断网或配置不可用 pip 源；失败显示阶段和日志、不打开浏览器、不记录成功。恢复网络/配置后再次启动成功。安装中按 Q，确认退出后按提示重建或重试。 |
| 环境失效 | 移动已启动过的项目、更换 Python 或使环境缺失；明确提示重建，用户重建后成功，开发环境和连接状态仍保留。 |
| 发布包不完整 | 删除 `dist/index.html` 或其引用的 JS/CSS；明确失败，不打开浏览器，服务和锁可清理。恢复完整 dist 后可启动。 |
| 重复启动 | 连续启动两次，包括安装期间和运行期间；只有一个服务/安装流程，运行期间第二次只打开已有页面。 |
| 端口冲突 | 使用其他程序占用 8000，再启动；显示端口与占用 PID，不杀其他程序、不换端口。另验证开发后端占用端口时的提示。 |
| 页面与 API | 检查 `/`、构建资源、`/api/health`、`/health`、连接/规则/应用设置 API；`/api/不存在` 返回 404，而不是 HTML。无效 `/api/app-settings` PATCH 的错误详情不包含输入值。 |
| UI 与本地业务 | 页面加载、切换设置、选择本地目录、浏览文件、组合规则、只读预览、确认执行均正常；不确认预览时不修改文件。刷新页面正常。 |
| OneDrive 授权 | 沿用原回调注册，连接授权弹窗正确通知发布页面，授权、重启后的刷新与测试项目预览/执行正常。确认日志不包含 OAuth code、Token 或授权请求完整 URL。 |
| 正常退出 | 分别按 Q、Ctrl+C；无执行时服务关闭、端口释放、再次启动成功；其他 Python 进程不受影响。关闭浏览器时服务继续运行。 |
| 执行中退出 | 发起较慢的测试批次后按 Q；停止接受新请求，等待执行完成及清理，不强杀。核对实际文件结果，确认没有遗留临时名称；不要盲目重试未知结果。 |
| 异常退出 | 关闭整个启动 PowerShell 进程，观察后端尝试正常停止；手动结束服务进程时启动窗口显示错误并保留日志。随后重启不受遗留 session/lock 文件影响。强杀后端时按实际文件核对未知写入结果。 |
| 浏览器与日志 | `-NoBrowser` 不自动打开；默认浏览器启动失败仍保留运行服务和可复制地址。错误窗口可阅读，stdout/stderr 日志可定位阶段，多次启动会清理旧日志。 |
| 更新保留数据 | 退出后替换完整前端及后端程序，保留状态文件；连接、偏好和授权仍存在，依赖是否重装符合清单变化情况。 |
| 开发回归 | 按原方式启动 Vite 和开发后端，验证代理/热更新；由用户运行后端 pytest、前端 `npm run check`，确认发布代码不要求开发模式存在 dist。 |
