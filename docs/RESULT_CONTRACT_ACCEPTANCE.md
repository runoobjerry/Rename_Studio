# 阶段四：结果契约与前端集成人工验收

此清单不表示运行验证已通过。Codex 只做静态检查；测试、编译、构建、浏览器验收由人工执行。本阶段的状态定义见[执行结果](api/executions/index.md#execution-outcomes)，升级条件见[契约迁移](api/common/errors.md#阶段四契约迁移)。

## 1. 测试与构建

在 `backend` 目录、项目虚拟环境中运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_api.py tests/test_execute_service.py tests/test_single_rename_service.py tests/test_storage_rename_contract.py tests/test_google_drive_provider.py tests/test_onedrive_provider.py
```

在 `frontend` 目录运行：

```powershell
npm run check
```

后端新增 API 用例以真实 Local Provider 和文件系统边界故障模拟“已写入但确认失败”，检查单项与批量 HTTP 200 响应直接序列化 `unknown`，而汇总仍为 `failed`，真实目标文件未撤回。批量 contract 用例检查未知后停止补组、`not_attempted` 与成功项保留。

前端复用真实 Hook、Store、Query 和组件，只模拟 API 边界：

- 原有混合成功、失败、未知/缺失结果用例保留，核对确认身份合并和缺失结果锁定；新增的四类结果计数及第三名称失败扩充场景已移除。
- 未执行与失败不依赖英文诊断，即使诊断为空也按状态及错误码显示；元数据缺失不单独决定结果状态。
- 未提供名称单独提示，未知继续显示待核对；前端第三名称显示的扩充断言已移除，实际名称展示按下方浏览器步骤核实。
- POST 目录和预览标为读取，执行标为写入；不通过 URL、HTTP 方法或供应商状态猜测。
- 工作台原有集成用例保留目录刷新失败、刷新成功及旧执行锁定检查；新预览等待、失败和成功的新增扩充断言已移除，后续恢复步骤按下方浏览器清单人工核实。

## 2. 配套升级

等待所有在途执行结束，核实异常结果后，再同步更新后端与前端并刷新页面。不要保留旧页面连接新旧不同契约的服务器，不在执行过程中升级。旧任务和旧预览不恢复，不自动迁移或重放；旧版三值结果后端与新版前端混用不受支持。

Network 中单项与批量结果的 `items[].status` 应直接为 `renamed / skipped / failed / unknown / not_attempted`，不应再用 `failed` 承载未知或未执行。汇总依然只有 `completed / partial / failed`；汇总 `failed` 不表示所有文件均已确认失败。无需新增第二份结果字段或恢复状态。

## 3. 浏览器检查

使用独立测试目录和可丢弃文件，分别在中英文界面检查：

1. 单项成功、规则批量成功和无变化项：真实文件名称正确，成功/无变化展示正确，旧预览不能再次执行。
2. 真实可复现的目标冲突或权限拒绝：显示相应原因；若响应未提供当前名称，显示“未提供当前名称”，不展示目标名作为已完成结果，也不据此显示未知。
3. 未知及混合结果以自动化测试的模拟 API 响应检查即可，不必对真实云盘制造网络中断或限流。浏览器如果自然遇到未知，目录刷新失败继续锁定；成功仅启用“刷新预览”，旧“开始修改”仍禁用；新预览成功后才可对新预览执行。
4. 结束任务后清理任务、选择和预览展示，真实文件不恢复、没有撤回请求、没有后台续跑。本阶段没有新增核对按钮或改变既有结束任务及解锁规则。

报告测试结果、两种语言的检查结果及未具备条件的项目即可。无需分享含凭据的网络载荷。没有实际云盘异常条件时，明确记录模拟验证与真实验证的区别。
