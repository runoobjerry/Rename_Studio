## 职责与边界

本文件只回答：当前改动落在哪里、哪些验证已有证据、还欠哪些验证或修复、下一步如何接力。

- 只记录当前工作，以及此前改动仍未关闭的具体问题或验收；待验收是针对这些改动的一次性事项，不是每轮必须执行的长期检查清单。
- 长期能力与维护约定归 [HANDOFF](FRONTEND_HANDOFF.md)，未来任务与长期巡检归 [TODO](UI_TODO.md)，可复用的检查步骤与标准归 [人工清单](UI_MANUAL_ACCEPTANCE.md)，测试/Git 流程归 [FRONTEND_TESTING](FRONTEND_TESTING.md)。本文件只引用，不复制完整内容。
- 每轮替换快照，不追加“上一轮/上一阶段”。没有具体改动或待解决问题时，不把全量工作流、视觉或性能检查列为当前待验收。
- 验证结论必须绑定日期、提交或工作区范围及命令/场景；区分未执行、静态检查、运行通过、失败和部分通过。历史通过不能证明当前版本通过。

## 验收后的处理

- **通过**：移除对应待验收项，在验证状态中简记版本范围、场景和结果；下一轮快照不继续保留已关闭记录，历史由 Git 保存。
- **失败**：保留复现条件、实际现象与待修复范围，修复后复验受影响部分；需延后安排的问题转入 TODO，本文件只保留任务编号和当前阻碍。
- **部分通过或未执行**：移除已通过部分，保留未通过/未执行的具体范围与原因；未执行不能标为通过。
- 后续代码再次影响已验收行为时，重新建立针对该改动的待验收项，不复活整份历史清单。

## 当前落点

- 单项快速改名直接提交执行，在服务端锁内复核最新源项、连接版本、名称、权限和冲突，不再创建预览；原批量预览及 preview_id 执行流程保持兼容，无状态格式迁移。
- 普通目录和固定任务内均支持单项改名；任务成员、原始 before 快照和其他成员结果保留，确认的文件身份与选择随结果更新。打开/取消不影响批量预览，提交时才使其失效。
- FileBrowser 唯一选中行显示 16px Edit 与 Tooltip；MUI Dialog 将文件主名和扩展名分为左右两个输入框，文件夹编辑完整名称，移除原文件名及说明文字。打开 Dialog 起暂停目录自动刷新；应用期间圆圈替换按钮文字，锁定输入与关闭，失败保留草稿，未知结果阻止再次写入。
- 补充单项工作流、行内入口、虚拟列表、Dialog 和工作台接线测试。长期约定见 [HANDOFF](FRONTEND_HANDOFF.md)，覆盖及操作标准见 [测试清单](FRONTEND_TEST_CASES.md)与[人工清单](UI_MANUAL_ACCEPTANCE.md)。
- 工作流内部适度拆分：`useRenameWorkflow` 保留对外接口、批量流程及协调；单项流程归 `useSingleRename`，公共执行请求和结果处理归 `useRenameExecution`。界面、API、Store 结构及现有测试入口保持不变，没有新增测试用例。
