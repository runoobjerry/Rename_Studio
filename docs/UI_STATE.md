## 职责与边界

本文件只回答：当前改动落在哪里、哪些验证已有证据、还欠哪些验证或修复、下一步如何接力。

- 只记录当前工作，以及此前改动仍未关闭的具体问题或验收；待验收是针对这些改动的一次性事项，不是每轮必须执行的长期检查清单。
- 长期能力与维护约定归 [HANDOFF](FRONTEND_HANDOFF.md)，未来任务与长期巡检归 [TODO](UI_TODO.md)，可复用的检查步骤与标准归 [人工清单](UI_MANUAL_ACCEPTANCE.md)，测试/Git 流程归 [FRONTEND_TESTING](FRONTEND_TESTING.md)。本文件只引用，不复制完整内容。
- 每轮替换快照，不追加“上一轮/上一阶段”。没有具体改动或待解决问题时，不把全量工作流、视觉或性能检查列为当前待验收。
- 验证结论必须绑定日期、提交或工作区范围及命令/场景；区分未执行、静态检查、运行通过、失败和部分通过。历史通过不能证明当前版本通过。

## 验收后的处理

- **通过**：移除对应待验收项，在验证状态中简记版本范围、场景和结果；下一轮快照不继续保留已关闭记录，历史由 Git 保存。
- **失败**：保留复现条件、实际现象与待修复范围，修复后复验受影响部分；需延后安排的问题转入 TODO，本文件只保留任务编号和当前阻碍。
- **部分通过或未执行**：移除已通过部分，保留未通过/未执行的具体范围与原因；未执行不能标为通过。
- 后续代码再次影响已验收行为时，重新建立针对该改动的待验收项，不复活整份历史清单。
