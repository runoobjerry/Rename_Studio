# UI 长期任务池

本文件回答“未来还有哪些事情要做？”。只保留未完成任务与延后需求，不记录近期完成历史、当前进度或本轮验证结果。当前接力快照见 `UI_STATE.md`；已实现能力与约定见 `FRONTEND_HANDOFF.md`。

任务编号保持稳定，优先级为建议顺序，不代表已经开始或获得新增功能授权。完成后移除条目；新发现的问题加入相应分组，不复用已移除编号。

设置页后续新增正文控件内文字（含下拉菜单项）默认使用主题 body2 排版；授权第二行、状态标签、辅助说明、提示和 Tooltip 使用 caption。相关视觉巡检验收文字层级与长文字布局，包含明暗主题下常规/重置组的字体、正文颜色一致性和禁用状态，以及重置确认 Dialog。

## P1：反馈与安全交互

- [ ] **UI-01 预览过期与恢复**：展示 `expires_at`，为 `PREVIEW_EXPIRED` 提供重新预览入口；不绕过服务端预览/执行校验，不自动执行重命名。
- [ ] **UI-04 错误与空状态恢复**：细化身份验证、Provider、校验、冲突、限流和部分执行的说明与可行操作，保留上下文详情，避免只用瞬时通知；预览过期由 UI-01 负责。

## P2：一致性、可访问性与质量保障

- [ ] **UI-05 视觉一致性巡检**：检查间距、排版、焦点、明暗主题状态对比度；持续验收共用菜单间距、面板共享图标操作（含筛选状态配色）及其 Tooltip 在长名称、复选框和窄屏下的表现；核对预览/执行后的筛选标签与行状态一致。维持共享默认值与紧凑控件尺度，不扩展为整体 CSS 重写。
- [ ] **UI-06 可访问性检查**：键盘遍历、焦点可见/恢复、表格语义、字段错误关联、实时状态播报及非颜色状态提示；验收新增/编辑连接名称的 10/11 字符保存边界、超限 Snackbar 提醒及缩短后保存；针对发现的问题做局部修复。
- [ ] **UI-07 响应式验收**：覆盖 320px 至桌面端的文件/预览表格、规则控件、Dialog、临时 Drawer、筛选菜单与通知；验收紧凑路径面包屑的连接名称首项、按宽度折叠/展开、父级菜单、长目录名截断与 Tooltip，以及不同水平内边距的30px操作按钮并排时的空间分配。检查设置分组卡片、主题下拉、连接表格内部滚动及新增/编辑 Dialog 的 standard 字段、右对齐保存、授权横向状态行、长账号信息与键盘焦点；长名称/长错误应在所属面板滚动，不撑破页面。
- [ ] **UI-08 通知与加载验收**：覆盖明暗主题、窄屏、连续通知、首次加载、后台刷新与失败；验收真实执行进度的长批次、临时改名/回滚、部分失败、轮询错误和完成收尾，区分已处理比例与成功比例；检查阶段标题、应用前后正文切换、透明轨道及轮询失败恢复/实际执行失败的文案区别。验收通知即时替换/原地淡出、正常反向退出与减少动态效果偏好，确认正常预览静默且上下文详情保留。实际验收进度只写 STATE。
- [ ] **UI-09 扩充回归测试**：补充工作区选择/预览重置、设置/OAuth、本地选择器失败、主题、加载/错误和 Dialog 边界；新增连接选择器草稿填充/取消/忙碌保护、编辑选择器成功/取消及账号退出通知已有回归源码，不重复添加。在已有规则菜单与默认路径测试基础上补充菜单键盘遍历/长描述、实际 OAuth 换号、失效目录恢复与窄屏交互验收；异步缓存切换用例须等待目标连接渲染，模拟响应与后续刷新保持一致。设置组件整理后复检授权加载/错误及缓存账号显示、操作禁用和弹窗关闭行为。复用既有测试工具，运行结果记录在 STATE，不由测试文件存在推断通过。
- [ ] **UI-10 组件维护性整理**：仅在相关需求暴露重复或维护困难时局部抽取；设置页采用简单控件紧凑排版、复杂 JSX 分支展开及命名操作函数的组织方式，避免恢复密集嵌套条件。四种规则字段保持清晰显式，不引入假设性的通用表单框架。共享控件样式归主题，布局/滚动/组件几何保留有针对性的 CSS。

## P3：性能观测后再优化
