# UI 长期任务池

只保留仍有价值的未完成任务和延后需求；已实现能力见 [HANDOFF](FRONTEND_HANDOFF.md)，当前落点与验证状态见 [STATE](UI_STATE.md)。详细测试覆盖和操作步骤分别查 [覆盖清单](FRONTEND_TEST_CASES.md)与[人工验收清单](UI_MANUAL_ACCEPTANCE.md)。

任务编号保持稳定，优先级为建议顺序，不代表开始实施或授权。开始前核对代码与现有测试，确认缺口仍存在；完成或取消即移除，不复用编号。不追加进度、完成历史或每轮视觉改动的验收细节。

## P1：反馈与安全交互

- [ ] **UI-01 预览过期与恢复**：展示 `expires_at`，为 `PREVIEW_EXPIRED` 提供重新预览入口。验收：过期可辨认，恢复必须生成新预览，不自动执行或绕过服务端校验。
- [ ] **UI-04 错误与空状态恢复**：按认证、Provider、校验、冲突、限流和部分执行提供说明及可行操作。验收：保留上下文详情，用户能判断下一步，未知写入不出现直接重试入口；预览过期由 UI-01 负责。

## P2：一致性、可访问性与质量保障

- [ ] **UI-05 视觉一致性巡检**：按人工清单检查侧栏、共享菜单、面板按钮、表格、设置与通知的排版和明暗主题状态。验收：颜色、间距与文字层级一致，长内容可读；只修复发现的问题。
- [ ] **UI-06 可访问性检查**：检查键盘遍历、焦点可见/恢复、表格语义、字段错误关联、状态播报及非颜色提示。验收：关键流程能用键盘完成，错误与忙碌状态可辨认。
- [ ] **UI-07 响应式验收**：覆盖 320px 至桌面端的工作区、设置、Drawer、Dialog、菜单与通知。验收：面包屑折叠/展开可用，长名称和错误在所属区域处理，控件可达且不撑破页面。
- [ ] **UI-08 通知与加载验收**：检查连续通知、首次加载、后台刷新、失败、减少动态效果偏好及真实执行进度。验收：通知替换/关闭无残留，加载不误报未连接；部分失败、回滚、轮询错误与执行失败正确区分，进度不虚构成功。
- [ ] **UI-09 回归覆盖补缺**：对照覆盖清单和源码，只补实际缺失的业务风险用例，优先工作区失效、设置/OAuth、选择器失败及异步缓存竞争。验收：测试断言最终行为，模拟数据与刷新一致；已覆盖场景不重复添加，视觉行为交人工验收；缓存切换后的 DOM 断言须等待目标界面更新，不能将缓存写入完成视为渲染完成。
- [ ] **UI-10 组件维护性整理**：仅在具体需求暴露重复或维护困难时局部抽取。验收：职责清楚、复杂分支可读，连接通用流程及字段输入类型消费 Provider 元数据，复用共享控件且保留现有行为；不引入通用表单框架或整体 CSS 重写。

## P3：性能观测后再优化

- [ ] **UI-11 性能基线**：复测大目录虚拟表格、完整集合选择/筛选、进度更新和重复预览/结束任务后的内存；对浏览器反复刷新后的内存增长，补充开发/生产构建对照及 GC 后存活内存观测。验收：记录提交、构建模式、浏览器、数据规模和测量方法，再决定是否优化；静态检查和普通 UI 验收不作为性能结果。

## 延后：需要明确需求或外部依赖

- **UI-12 规则集 UI**：依赖 RuleSet API 与持久化，接口可用且需求确认后开展。
- **UI-13 历史/撤销/重做**：依赖后端 API、持久化及安全语义，不提前展示可用入口。
- **UI-14 扩展文件操作**：搜索及其他筛选，先明确使用场景与 API 支持；现有文件名/修改时间排序、文件类型与预览状态筛选和表格虚拟化不属于待实现能力。
- **UI-15 扩展编辑体验**：拖放排序、快捷键、规则模板、高级工作流和深入品牌设计，按明确需求开展。
- **UI-16 扩展能力 UI**：其他云盘 Provider、高级规则与插件 UI，依赖后端能力和前端字段适配；Local/OneDrive 多连接已有实现。
