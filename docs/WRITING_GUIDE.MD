# 文档写作指南

[文档索引](README.md) · [开发行为规范](../AGENTS.md) · [临时文档规则](generated/README.md)

本指南供人类和 AI Agents 编写、维护、审查 Rename Studio 文档时使用，适用于仓库知识库，以及与其关联的用户帮助和发布说明。写作目标是让读者找到可信的答案、完成当前任务，并能沿链接核对依据。

文档归属与导航见[文档索引](README.md#文档职责)，Agent 的操作权限见 [AGENTS.md](../AGENTS.md)。已有页面按本次修改范围逐步对齐写作约定。

## 确定读者与归属

动笔前明确读者要解决的问题，以及读完后应能完成的操作或判断。先查找已有主题页，能在原页解决的问题直接更新原页；新增页面应有独立用途和索引入口。

按下表选择内容重点。它用于判断写什么，具体文件职责与完整目录继续由[文档索引](README.md)维护。

| 文档类型与现有入口 | 读者需要的内容 | 内容边界 |
| --- | --- | --- |
| 用户入口：[项目 README](../README.md)、[扩展 README](browser-extensions/README.md)，以及首页链接的 Wiki | 能做什么、支持范围、准备条件、操作步骤、可观察结果、常见问题的处理 | 用户步骤使用界面名称；内部类名和调用链放入开发文档。Wiki 已负责的详细主题从入口链接过去 |
| 运行与开发：[快速开始](../README.md#快速开始)、[DEVELOPMENT](DEVELOPMENT.md)、[扩展开发](browser-extensions/DEVELOPMENT.md) | 区分发布包与源码、系统与 Shell、执行目录、命令、产物和退出方式；发布操作说明触发条件与核对点 | 区分本体和扩展的版本、构建及发布流程；运行权限引用 AGENTS，具体测试入口引用 TEST |
| 系统与模块架构：[系统](ARCHITECTURE.md)、[前端](frontend/ARCHITECTURE.md)、[后端](backend/ARCHITECTURE.md)、[扩展](browser-extensions/ARCHITECTURE.md) | 职责、依赖、状态归属、关键流程、约束、扩展入口及必要的设计原因 | 顶层说明跨端关系，子系统说明内部结构；链接实际代码入口，避免逐函数复述或复制完整目录树 |
| 接口参考：[API](api/README.md) | 对象、方法与路径、参数、默认值、返回值、错误、示例及客户端可观察行为 | 保留现有资源索引与端点结构；实现调度、内部锁和缓存算法放入架构文档 |
| 设计规范：[UI_DESIGN](frontend/UI_DESIGN.md) | 设计目标、修改导航，以及视觉、布局、交互、可访问性与 UX 文案准则 | 只说明设计要求；具体实现入口与逻辑由前端架构维护，某次验收结果另记 |
| 测试与验收：[前端 TEST](frontend/TEST.md)、[后端 TEST](backend/TEST.md)、[响应丢失模拟](frontend/TEST_MANUAL.MD) | 风险对应的测试入口、编写约定、运行条件、操作、预期结果及证据边界 | 长期页维护方法；具体版本的执行结果按需进入任务记录。专项手动场景保持其明确范围 |
| Agent 指令：[根级 AGENTS](../AGENTS.md)及目录级指令 | 行为、权限、完成标准和按任务阅读入口 | 目录级只补充特有约定，架构事实和写作细则链接到负责它们的文档 |
| 阶段记录：[generated](generated/README.md) | 范围、验收条件、决定、进展、证据、阻碍和下一步 | 标明任务状态；稳定结论迁入长期文档，完成或取消后按目录规则清理 |

同一事实集中在负责它的文档维护。其他页面保留理解当前任务所需的一两句摘要，再链接完整定义。例如，用户步骤应当提醒未知结果需要核对；逐项状态枚举和字段表仍由 API 文档维护。

## 核对事实

### 先确认版本和证据

默认核对当前工作区；面向某个发布版本时，核对指定标签或提交。开始前查看已有修改，区分工作区、暂存区和已发布代码，保留用户已有改动。仅为查资料不切换分支或覆盖文件；可读取指定版本的文件。

| 要写的事实 | 核对入口 | 能据此说明什么 |
| --- | --- | --- |
| 请求字段、枚举、默认值、错误 | [Schema](../backend/app/schemas)、[路由](../backend/app/api)、相关 Service / Provider、[前端类型](../frontend/src/types/index.ts)和[客户端](../frontend/src/api/client.ts) | 类型定义结构，调用链说明处理条件与返回语义 |
| 界面名称与交互 | 相关组件、工作流 Hook、[语言资源](../frontend/src/locales)、[UI 规范](frontend/UI_DESIGN.md) | 标签、触发条件和设计要求；浏览器验收记录真实布局与交互结果 |
| 配置、命令、产物与 CI | 配置读取代码、包脚本、启动/打包脚本和[工作流](../.github/workflows) | 默认值、生效条件、命令行为与工作流范围；执行结果查对应日志 |
| 回归与验收结论 | 对应版本的测试输出、用户报告、CI 记录或任务证据 | 指定环境、范围和时间的结果；测试源码用于定位用例与断言 |
| 第三方限制与行为 | 对应版本的官方文档及项目适配实现 | 第三方提供的能力与项目实际支持范围，二者分别表述 |

追踪与本次结论有关的直接调用方和返回结果即可。纯拼写、链接或措辞修改无需通读所有实现；但“始终”“只会”“自动”“支持所有”等强断言需要相应证据。

文档、代码和验证结果不一致时，先定位差异。若实现违反既定契约，记录问题并提出修复范围，不把规范悄悄改成现有缺陷；若文档陈旧，更新负责该主题的页面及引用。证据不足时明确待核对项，不把推测写成既定能力。

### 区分现状、要求与结果

- **当前行为**：说明触发条件和可观察结果，并给出实现或契约入口。
- **设计要求**：使用“必须”“应”等词说明约束，实现情况按代码和验收结果记录。
- **建议或待实现方案**：说明适用场景和取舍；未采纳的方案按需留在有状态的任务记录中。
- **验证结果**：注明日期、提交或工作区范围、执行者、环境、命令或场景、实际结果及限制。用户报告标为用户执行，CI 结果注明对应提交。

静态核对写明所查文件与结论，测试和验收写明实际执行的命令、场景及结果，待执行项单独列出。Mock、真实云盘和各平台的验证分别记录适用环境。记录格式复用 [generated 的模板](generated/README.md#最小记录模板)，简单任务在交付说明中报告即可。

### 保留影响操作的边界

简化表达时保留主体、条件、例外与后续动作。涉及写入的说明核对[业务与安全不变量](ARCHITECTURE.md#业务与安全不变量)，详细契约由对应 API 页维护。以下是本项目中容易写错的例子：

| 容易误导的写法 | 应表达的内容与依据 |
| --- | --- |
| 所有重命名都必须先预览 | 批量执行使用预览；单项直接执行遵循[独立契约](api/executions/single.md) |
| 请求超时说明改名失败，可以重试 | 响应丢失可能发生在写入之后；先核对实际结果，不能盲目重发。参见[未知结果核对](ARCHITECTURE.md#不确定写入的核对) |
| HTTP 200 表示所有文件改名成功 | 同时检查整体结果和逐项状态，具体含义见[执行结果](api/executions/index.md#execution-outcomes) |
| 目录读取使用了缓存，所以执行也无需重新读取 | 浏览缓存与批量执行前的实时复核是不同流程，见[后端目录读取模式](backend/ARCHITECTURE.md#目录读取与缓存) |
| CI 通过，说明 OAuth 和真实云盘操作通过 | 只陈述该工作流实际执行的检查；真实环境验收另列证据 |

## 组织与表达

先给读者当前需要的答案，再补条件、步骤或原因。操作页按“前提 → 操作 → 结果 → 必要的故障处理”展开；架构页按职责和关系解释；参考页便于按字段、对象或接口查找。根据内容选结构，不要求每页填满同一模板。

步骤在读者作出选择之前说明适用条件。例如，开发版和发布版扩展的加载步骤开始前，就应确定配套的本体地址。真实写入、删除配置等有后果的操作，把具体提醒放在执行前，并提供可行的核对或恢复方式。

| 读者要做什么 | 优先形式 |
| --- | --- |
| 理解因果、职责或设计取舍 | 连贯段落，每段围绕一个问题 |
| 按顺序完成操作 | 编号步骤，每步有明确动作；简单操作可用一句话 |
| 找到自己的情况 | 按条件区分的无序列表 |
| 比较选项或查询字段 | 同一组列的表格，长解释移到表格外 |
| 复制命令、请求或配置 | 带语言标记的代码块，前面写清运行条件 |
| 理解跨模块关系或异步时序 | 必要的 Mermaid 图，配简短文字说明 |

使用自然、具体的中文。操作说明先说位置和动作，技术解释直接说主体与行为。删去“赋能”“全面提升”“值得注意的是”等没有增加信息的措辞，不用“显然”“只需”“很简单”代替步骤和前提。一句话承载多个独立判断时拆开；相连的推理保留为段落。

直接呈现判断、逻辑和依据，删除段落末尾重复的否定式限定与免责铺垫。涉及限制或权衡时，写清条件、后果和可采取的动作。例如，把“构建成功不能证明实际可用”改为“构建后从产物加载扩展，核对按钮、账号匹配和目录打开流程”。精简时保留必要的解释、例子和衔接；未知写入、权限、取消收尾等业务规则按具体契约准确表达。

例如，把“本系统具备完善的预览能力，可有效保障用户操作的安全性”改为“生成预览后，检查新名称与冲突，再确认执行”。这让读者知道下一步要做什么、检查什么。

“必须”用于明确契约和必要条件，“建议”用于有取舍的选择，“可以”用于可选操作。介绍可调参数时说明单位、默认值来源、生效条件和调大/调小的影响；默认值留在负责该配置的页面或配置源，其他页引用，不扩散数值副本。

## 术语

用户文档使用当前界面上的名称，开发文档按对象职责使用技术术语。第一次出现容易混淆的术语时解释其含义，之后保持一致；HTTP 字段、代码标识符、错误码和枚举保持原样，不为中文行文翻译或改写。

| 概念 | 本项目的写法与区分 |
| --- | --- |
| 产品 | 正文使用 Rename Studio；仓库名、路径等精确标识保留 `Rename_Studio` |
| Storage / 文件来源 | 用户界面沿用“文件来源”；开发文档中的存储连接是按 `storage_id` 标识的配置实例，字段含义见[存储连接](api/storages/index.md) |
| Provider | 存储服务类型、定义与实现；`provider_type` 区别于 `storage_id`。Local、OneDrive、Google Drive 的支持范围以项目契约为准 |
| 连接与授权 | 说明是在创建/修改存储配置、发起账号授权还是断开账号。不要把“配置已保存”写成“账号已授权” |
| 位置、路径与文件 ID | `StorageLocation` 是位置对象，路径用于相应的浏览或展示上下文，ID 表示资源身份；按[位置契约](api/common/locations.md)区分，不能从显示路径猜云盘 ID |
| 预览与执行 | 预览用于查看和校验；执行可能修改真实文件。明确是批量还是单项，不能混用各自的请求与流程 |
| 失败、未知与未尝试 | 采用[逐项状态](api/executions/index.md#execution-outcomes)的含义；未知表示结果无法确认，未尝试表示尚未执行，均不能笼统改写为失败 |
| 刷新 | 写清应用内目录刷新、浏览器整页刷新或 Token 刷新；说明缓存时区分前端查询缓存与后端目录缓存 |
| 版本 | 区分本体版本、扩展版本、消息协议版本和连接 `revision`，按所在契约准确命名 |

界面标签核对 [zh-CN](../frontend/src/locales/zh-CN) 和 [en-US](../frontend/src/locales/en-US) 资源及调用处。API 和 i18n 键沿用既有标识；任务同时修改固定 UI 文案时，同步两种语言。用户输入的名称、路径和账号信息保持其数据语义，示例另行脱敏。其他语言的文档保持事实、示例和链接一致，使用该语言自然的表达。

## 格式与链接

### Markdown 与层级

使用 UTF-8 的普通 Markdown，以仓库阅读体验为准。新增长期文档放入 `docs/` 对应主题目录，目录级 Agent 指令仍留在代码目录；命名沿用所在目录约定，普通主题页采用简短、可读的文件名。引用时保持路径和扩展名大小写一致，不为本次写作批量改名。

新建独立说明页通常使用一个一级标题，正文从二级标题开始，不跳级。现有 API 子页沿用资源/端点层级及显式锚点，保留 `Parameters`、`Returns`、`Errors` 等既有结构，不为了统一标题破坏引用。长页提供章节导航，标题表达具体主题或任务。

标题、段落、列表、表格和代码块之间留一个空行。无序列表使用 `-`，有顺序的操作使用编号；子内容缩进到所属列表项，避免把步骤的示例渲染成新的独立段落。完整句子使用句号，短标签无需强加标点。

中文正文使用中文标点，中英文和数字之间保留适当空格，例如“调用 API”“等待 2 秒”；代码、路径、URL、界面原文保持精确内容。按钮和菜单标签使用粗体，如 **应用**；字段、命令、错误码和需精确输入的值使用反引号，如 `storage_id`。正文不整段加粗。

提示优先写成就近的短段落；确需突出时使用引用块或 GitHub 的 `NOTE` / `WARNING` 提示。必须完成的步骤留在正文，不把关键前提藏进折叠内容。保留必要的安全提醒，避免整页堆叠提示框。

### 导航与引用

每份文档都必须可从[文档索引](README.md)到达：长期文档在总索引登记，API 子页由 [API 索引](api/README.md)逐级索引，临时文档由 [generated 索引](generated/README.md)登记。仓库首页与扩展 README 也应链接回总索引。

文档开头提供所属索引的返回链接和直接相关文档链接。资源子页返回领域索引，领域索引再返回总索引。新增、移动、删除页面及修改标题时，同步索引、所有引用和返回链接；删除过时说明，历史交给 Git，不保留无明确需求的兼容占位页。

仓库内通常使用相对链接；精确文件名仅作为说明时可用行内代码，用作阅读入口时应可点击。链接文字说明目标内容，避免“这里”“点击查看”。

跨页面引用优先使用现有稳定锚点。改动标题时检查所有引用；API 已有 `<a id="..."></a>` 应继续保留。代码入口链接到实际文件或目录，避免依赖经常变化的行号；需要保存历史证据时，可链接到明确提交的代码页面。

**发布包 README 是在线链接的例外。** 根 README 会直接进入发布 ZIP，开发知识库不在包内，因此它指向知识库和 Wiki 的导航使用 GitHub 在线地址；包内实际存在的文件仍可使用相对链接。打包范围以[组包脚本](../scripts/build_release.py)和[发布说明](DEVELOPMENT.md#本地组包与检查)为依据。不要为统一相对链接而破坏发布包导航。

外部依据优先链接官方文档的相关页面或章节。涉及版本差异、第三方限制和一次性验证的结论，记录适用版本或查阅日期。引用保留支持当前判断的必要内容，用自己的话解释对本项目的影响；采用外部方法时说明在本项目中的适用方式。

### 图片与图示

只有文本难以表达布局、入口或流程时才加图。截图聚焦相关区域，使用测试数据并移除账号、Token、真实文件名等敏感信息；配说明用途的替代文本，图片丢失时正文仍应保留关键步骤。素材放在所属主题下有明确用途的目录，通过相对路径引用，随界面变化同步更新或删除。

Mermaid 图只展示当前讨论的模块、状态或时序，箭头含义与代码一致。描述失败、取消或未知结果时保留相关分支，不能用一条成功路径概括全部行为。无需为纯措辞或简单单步操作增加图示。

## 命令与示例

命令前说明适用系统、Shell、工作目录、必要依赖和执行者；有多个终端时分别标注。命令后说明预期输出或观察点，诊断输出与输入命令分开。PowerShell 和 Bash 示例各自核对，不能混用环境变量、路径或续行语法。

代码块标注语言，例如 `powershell`、`bash`、`http`、`json`、`toml`、`text`。可复制的命令不包含提示符和伪输出；占位符在块外说明替换方式。标为 JSON 的完整示例使用有效 JSON，省略片段明确标为节选，不能把 `...` 当作合法字段值。

API 示例与同页参数、对象和错误表一致。区分字段省略、`null`、空字符串和默认值；前缀遵循 [API 通用约定](api/common/conventions.md)，不要混用文档路径与实际浏览器请求地址。选取能说明正常操作和重要差异的示例，不穷举机械变体。

例如，说明“手动完整刷新云目录”的请求体可沿用[目录 API](api/directories/list.md)：

```json
{
  "location": { "kind": "id", "value": "folder-id" },
  "refresh": true
}
```

这里的 `folder-id` 替换为当前连接内的真实目录 ID；这是请求体示例，完整路径、响应及错误继续引用 API 页。若示例条件改变为外部导航，需要重新核对参数组合，不能只改标题。

写入、重置或删除示例说明真实后果，使用测试文件副本或专用环境。凭据、Cookie、账号数据及未经脱敏的请求响应不进入正文、截图或附件。示例注明执行者和运行条件，执行记录填写实际结果。本地安装、编译、测试、构建和浏览器验收遵循 [AGENTS 的验证约定](../AGENTS.md#验证与交付)。

## 维护流程

1. **确定范围。** 找到读者问题、负责该主题的页面和适用版本，查看已有改动。简单勘误直接定位相关段落；复杂跨模块任务按需使用 [generated](generated/README.md) 留下接续记录。
2. **核对依据。** 沿相关代码、配置、契约或验证证据确认事实，标出不确定项。只把读者需要的结论写入正文，研究过程无需全部搬入文档。
3. **更新主题页。** 重写过时段落，保留仍有效的约束与稳定锚点。长期文档描述当前结构和规则，变更历史进入 Git 或发布说明，不在原页不断追加“本次更新”。
4. **同步关联内容。** 根据下表检查受影响的文档、示例和引用，范围由真实变化决定，不机械更新所有页面。
5. **分别复查事实和阅读体验。** 先核对字段、状态、代码入口和证据，再以首次阅读者视角检查前提、顺序、术语、步骤与结果。AI Agents 同样完成这两次复查，不需要额外搭建文档工具链。
6. **完成静态收尾并交付。** 检查改动范围、Markdown、路径大小写、链接目标、锚点和空白问题；准确报告已检查与未验证事项。本地运行验证、Git 和发布操作遵守既有权限。

| 变化 | 需要检查的关联项 |
| --- | --- |
| API 字段或结果语义 | 对象定义、端点、错误说明、请求/响应示例，以及引用这些契约的架构和操作说明 |
| 状态归属、调用链或模块入口 | 对应架构页、代码链接和相关流程；跨端边界变化再同步系统架构 |
| UI 名称或交互 | 用户步骤、截图、设计约定及适用的验收方法；涉及 UI 文案时检查语言资源 |
| 配置、命令、版本或发布行为 | 开发/启动说明、相关 README、工作流范围和发布说明；本体与扩展分别核对 |
| 页面或章节增删移动 | 所属索引、返回导航、交叉引用、已有锚点及代码中指向文档的链接 |
| 阶段任务完成或取消 | 稳定结论迁入长期页，按 generated 规则清理临时页和索引项，保留必要的未决事项 |

发布说明写明本版本对用户的影响、兼容性变化和必要操作；破坏性变化给出迁移方法。尚未发布的工作区实现不能写成已发布能力。若本次只能修改仓库文件，关联 Wiki 或其他外部资料的待同步项应明确列出，不能声称已经更新。

## 交付前检查

- [ ] 读者、任务和适用版本明确，页面放在负责该主题的位置。
- [ ] 行为已核对相关实现或证据；现状、要求、建议和验证结果没有混写。
- [ ] 主流程可读，关键前提在操作前，失败或未知结果有正确的后续动作。
- [ ] 术语、UI 标签、字段、默认值和示例一致，保留批量/单项及 Provider 差异。
- [ ] 索引、返回链接、相对路径、大小写和锚点有效；发布包导航仍可使用。
- [ ] 命令注明环境和目录，示例可辨认、已脱敏，没有编造输出或通过记录。
- [ ] 过时内容已替换，长期页面没有累计临时进度、测试数量或版本通过状态。
- [ ] 交付说明列明修改文件、主要变化、实际静态检查及未验证范围；外部待同步项和剩余问题明确。

检查按任务适用性执行：纯文案任务检查措辞、结构和链接；涉及命令、界面或业务步骤且尚未实际执行时，列出需要用户核验的具体事项。
