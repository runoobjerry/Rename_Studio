## 设计目标与修改入口

工作台优先帮助用户看清文件、规则、新名称与执行结果。主操作路径为“选择 → 组合规则 → 预览 → 确认执行”，单项编辑使用独立入口。信息密度服务于比较与核对，避免装饰挤占名称和错误详情。

| 面板、列布局、滚动与断点 | [styles.css](../frontend/src/styles.css)、[WorkspaceApp](../frontend/src/WorkspaceApp.tsx) |

| 表格与虚拟化 | [FileBrowser](../frontend/src/features/files/FileBrowser.tsx)、[PreviewPanel](../frontend/src/features/rename/PreviewPanel.tsx)、[useVirtualTable](../frontend/src/hooks/useVirtualTable.ts) |

## 视觉风格

采用 [MUI v9 的 Material UI](https://mui.com/material-ui/) 与 [Material Design 2](https://m2.material.io/design/introduction) 设计语言，结合项目现有视觉风格保持一致。

- **整体气质**：清晰、克制、适合持续操作的工具界面。保留绿色强调色与明暗双主题，避免大面积高饱和装饰、无意义渐变和过强阴影。
- **颜色语义**：强调色突出主要操作与当前选择；成功、警告、错误和普通信息使用稳定且可区分的语义。状态同时提供文字或图标，不能仅靠颜色表达。两种主题均应保证文字、边界、焦点与状态可辨识。
- **文字层级**：页面标题、区域标题、正文和辅助信息层级清晰。同类信息保持一致的字号、字重与行距，辅助文字不得因弱化而难以阅读，长文件名和结果说明保有足够阅读空间。
- **形状与层次**：同类控件保持一致的圆角、边框、图标比例与留白。用对齐、间距和分隔表达分组，用适度阴影区分浮层，避免每个区域都依赖厚重边框或卡片堆叠。
- **控件与状态**：按钮、输入框、菜单、表格、标签和对话框保持统一的视觉语言。默认、悬停、聚焦、选中、禁用、加载和错误状态应可辨识；主要操作比次要操作更突出，高风险操作有明确区分。

## 布局规范

- **任务关系清晰**：文件、规则、预览与执行区域的位置应帮助用户理解操作顺序，便于比较原名称、新名称和结果。主要操作靠近其作用对象，避免跨区域寻找。
- **对齐与密度一致**：同层级区域保持统一的对齐、间距与控件密度。高频信息优先展示，辅助说明就近提供，避免重复工具栏和过多嵌套分组。
- **表格便于核对**：名称、选择、状态与操作各有稳定空间。行内操作出现、状态更新或内容加载时，避免无必要的行列跳动；不能因压缩布局而隐藏关键结果。
- **适应窗口与语言**：窄窗口、页面缩放及不同语言长度下，核心任务仍可完成。重排后保留内容顺序和操作关系，不重叠、遮挡或将关键操作挤出可达范围。
- **长内容可读**：文件名、路径、来源名称和错误说明在所属区域内合理换行、截断或滚动；截断后提供读取完整内容的方式。导航始终能识别当前位置并找到返回路径。
- **浮层不阻断阅读**：菜单、对话框与通知的位置和大小应保留上下文，滚动后仍能访问必要操作；焦点和关键信息不得被浮层遮挡。

## 交互设计规范

- **操作可预期**：相同操作使用一致入口；点击前能判断作用对象、范围与结果。不可用操作应能让用户理解原因，不展示尚未支持却看似可用的功能。
- **状态各自清晰**：区分首次加载、刷新、空内容、没有选择、未授权与读取失败。刷新时保留可用上下文，不能把错误呈现为空目录或授权失效。
- **反馈及时且真实**：操作后及时反馈，进度与结果有实际依据。区分全部完成、部分完成、失败和结果未知；未确认结果应引导核对，不能暗示可直接重试或已经成功。
- **写入与风险透明**：明确预览与真实修改的区别。批量执行及不可撤销或高风险操作在确认前说明对象、影响范围与后果，确认按钮直接表达将发生的动作，不承诺尚未提供的撤销或恢复能力。
- **表单便于修正**：标签表达字段用途，必要说明与错误靠近对应输入。输入有误时保留可修正内容，并提供清晰下一步；保存、取消和关闭的含义保持一致。
- **忙碌与取消明确**：进行中的操作可被识别，避免重复提交或相互冲突的操作。按业务允许的阶段提供取消或关闭入口，说明关闭后正在执行的操作如何处理、已完成的修改如何保留。
- **反馈就近且适度**：字段问题在字段附近说明，持续问题在相关区域保留，短暂通知用于及时告知结果。重要结果与恢复动作不能只存在于自动消失的通知或悬停提示中。
- **键盘与辅助访问可用**：核心流程可用键盘完成，焦点顺序符合阅读顺序、位置清晰，关闭菜单或对话框后返回合理位置。图标操作有可读名称，字段的标签、说明与错误关系清楚。
- **兼顾不同操作方式**：触屏下无需悬停也能发现并完成关键操作，操作目标与间距便于准确点击。动态效果简短、服务于状态理解，并尊重减少动态效果的偏好。

## UX 文案规范（UX Writing）

所有面向用户的界面文本，包括按钮、标题、提示、状态、错误和确认对话框，均遵循以下规则：

1. **准确清晰**：准确表达实际功能与状态，优先使用用户熟悉的语言，避免内部技术术语和模糊表述。
2. **简洁直接**：重要信息前置，删除冗余解释和重复内容，但不得为追求简短而损失必要信息。
3. **行动导向**：按钮和操作提示使用明确的动词，确保用户能够预判操作结果。
4. **术语统一**：同一功能、对象及状态使用一致的名称，优先沿用项目现有术语，不随意创造同义表达。
5. **状态真实**：明确区分成功、失败、部分完成和结果未知，不夸大结果，不将未知状态直接描述为失败。
6. **错误可恢复**：错误提示应说明问题、影响及可执行的下一步；避免空泛报错、责备用户或直接暴露内部异常。
7. **语气自然**：保持客观、友好、克制，避免过度礼貌、感叹号、营销化和拟人化表达。
8. **格式规范**：中文标题和按钮不加句号；数字、单位、专有名词及标点格式保持一致。
9. **风险透明**：不可撤销或高风险操作应明确说明影响范围与后果，使用具体的确认按钮文案。

修改文案时，应结合实际业务逻辑与界面上下文判断，优先复用已有表达；不得仅为了润色而改变业务含义。
