# Frontend Codex 指令

以下规则仅适用于 `frontend/`。业务约定见 `../docs/FRONTEND_HANDOFF.md`，测试流程见 `../docs/FRONTEND_TESTING.md`。

- 改动前定位受影响的组件、状态或 API 行为，优先复用已有的 Vitest + Testing Library 测试，测试文件与源文件相邻。
- 修复 Bug、修改规则配置/文件选择/目录导航/预览/执行/连接状态等实际业务行为时，增加或更新能复现问题的回归测试。只修改样式、文案或布局时，不为测试覆盖率而编造无业务价值的测试。
- 验证用户可观察行为、关键状态与请求参数；模拟 API 响应，严禁在测试中连接真实 OneDrive、改名真实文件或使用用户凭据。不要大量使用无意义快照、内部实现细节断言及不稳定的计时等待。
- 改动后先运行受影响测试：`npm test -- src/相应路径/文件.test.tsx`（在 `frontend/` 下）。提交前运行 `npm run check`，它会执行全部 Vitest 测试、TypeScript 检查和生产构建。
- 若测试失败，定位原因并修复；不能通过删除测试、跳过断言或降低检查强度使其“通过”。环境不允许运行时，明确报告“未运行”及原因，不声称通过。
- 只处理本次变更有关的失败，不顺带重构无关代码。真实浏览器响应式、视觉和云端授权/重命名操作仍需人工验收。
